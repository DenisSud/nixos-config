# NixOS Configuration

My NixOS config, supporting two hosts:

- **`pc`** — Desktop, AMD Ryzen + NVIDIA RTX 5070 (Blackwell). The "decked out" machine: Docker, Steam + gaming stack, Xray proxy.
- **`g14`** — ASUS ROG Zephyrus G14 laptop, AMD Cezanne iGPU + NVIDIA RTX 3050 Mobile (hybrid). The "lite" machine: no Docker, no Steam. Adds `asusctl` + `supergfxd` for power/profile/dGPU-mode control

Dotfiles are managed as separate git repos and symlinked into place (out-of-band from NixOS):

- **[dotfiles-shell](https://github.com/DenisSud/dotfiles-shell)** — Fish + Starship + Ghostty
- **[dotfiles-nvim](https://github.com/DenisSud/dotfiles-nvim)** — Neovim config
- **[dotfiles-pi](https://github.com/DenisSud/dotfiles-pi)** — Pi coding agent config

## Repository Structure

```

├── flake.nix                       # Flake entry point: nixpkgs + rip + pi inputs
│                                   #   (asusctl/supergfxd built-in)
├── flake.lock
├── AGENTS.md                       # This file
│
├── pkgs/                           # Vendored package expressions
│   ├── happ.nix                    # Happ desktop client, repackaged from
│   │                               #   the upstream .deb (see modules/happ.nix)
│   ├── anime-matrix/               # AniMe Matrix lid helper: gif/image/
│   │                               #   video/text -> asusctl (modules/asus.nix)
│   ├── parakeet-typing/            # Parakeet TDT v3 IBus engine + dataset

│   └── parakeet-indicator/         # GNOME Shell waveform pill extension

    ├── desktop.nix                 # GNOME + gdm                   (common)
    ├── fonts.nix                   # Inter + JetBrains Mono        (common)
    ├── services.nix                # openssh, flatpak, appimage,
    │                               #   polkit, nix-index           (common)
    ├── printing.nix                # CUPS + Avahi, Epson L3271
    │                               #   (L3270 series) queue        (common)
    ├── dev-tools.nix               # LSPs, formatters, tree-sitter,
    │                               #   gcc, pkg-config, nodejs     (common)
    ├── shell-utils.nix             # bat, fd, eza, gh, etc. + shell
    │                               #   aliases + session vars      (common)
    ├── web-search.nix              # SearXNG + web_fetch backends  (common)
    ├── user.nix                    # denis user + base user pkgs   (common)
    ├── programs.nix                # fish/zsh, direnv, gnupg, mtr  (common)
    ├── vial.nix                    # Vial udev rules               (common)

    │                               #   denis.asus.animeMatrix.enable
    └── voice-typing.nix            # denis.voiceTyping.enable
```

**Pattern:** `modules/shared.nix` is the shared layer. It imports every common
module and every optional feature module, declares the `denis.*` options, and
applies the non-host values in `config`. Optional stacks declare
`denis.<feature>.enable` (via `lib.mkEnableOption`, default `false`) and guard
their config with `lib.mkIf`. Host files in `hosts/` import
`../modules/shared.nix`, set `denis.*` values, and keep only genuinely
host-specific hardware config (NVIDIA/Prime, file systems). To toggle a feature
on a host, set the corresponding `denis.<feature>.enable`.

**`denis.*` options:** `denis.hostName` (`str`), `denis.firewall.enable`
(`bool`, default `true`), `denis.latestKernel` (`bool`, default `false`),
`denis.ipForward` (`bool`, default `false`), `denis.userPackages`
(`listOf package`, default `[]`), and the feature toggles `denis.docker.enable`,
`denis.gaming.enable`, `denis.xray.enable`, `denis.happ.enable`,
`denis.wakeOnLan.enable`, `denis.tmux.enable`, `denis.asus.enable` (all
`bool`, default `false`), plus `denis.asus.animeMatrix.enable` (nested under
`denis.asus.enable`) for the AniMe Matrix lid helper.

## Machines

### `pc` (Desktop)
- Hostname: `pc`
- GPU: NVIDIA RTX 5070 (Blackwell) with **open** kernel module
- Kernel: `linuxPackages_latest`
- systemd-boot
- Docker enabled
- Steam + full gaming stack
- Xray proxy service (reads `/etc/xray/config.json`)
- Happ proxy client + `happd` TUN daemon (`denis.happ.enable`; package
  vendored in `pkgs/happ.nix`, repackaged from the upstream .deb)
- LibreOffice, DaVinci Resolve (free, unfree package) + ddcutil-based monitor brightness GNOME extension
- Parakeet v3 voice typing (`denis.voiceTyping.enable`): IBus engine +
  floating waveform pill; model runs on CPU

### `g14` (Laptop)
- Hostname: `g14`
- GPU: AMD Cezanne (integrated) + NVIDIA RTX 3050 Mobile (hybrid)
- NVIDIA Prime offload mode (dGPU on demand via `nvidia-offload` or `supergfxctl`)
- Proprietary NVIDIA kernel modules (open modules don't play well with Prime hybrid yet)
- **Full ASUS Linux stack** (built into nixpkgs, no extra flake input): `services.asusd` (profiles, fan curves, AniMe matrix, LED keyboard, ROG Control Center GUI) + `services.supergfxd` (dGPU mode switching)
  - **Note**: `supergfxctl` is being phased out upstream — only keep it if you need vfio for VMs or have dGPU power-off issues. See https://asus-linux.org/guides/nixos
- **No** Docker or Steam — keeps rebuilds fast. LibreOffice (Writer/Calc) is installed as a user package.
- AniMe Matrix lid display (`denis.asus.animeMatrix.enable`): custom gifs,
  images, video and text via `anime-matrix` (see "AniMe Matrix" below). The
  panel is a GA401 33 x 55 diagonal lattice, 16 grey levels.
- Parakeet v3 voice typing (`denis.voiceTyping.enable`), same engine and
  model as pc (CPU; ~1.1 GB resident while the engine process is alive)
- Default kernel (no `linuxPackages_latest`)

## Applying Configuration

### Build (dry-run)
```bash
sudo nixos-rebuild dry-build --flake .#pc
# or
sudo nixos-rebuild dry-build --flake .#g14
```

### Switch
```bash
sudo nixos-rebuild switch --flake .#pc
# or
sudo nixos-rebuild switch --flake .#g14
```

### Using `nh` (Nix Helper)
```bash
# From any directory — nh reads the flake path from config (set in modules/nix.nix)
nh os switch
nh os boot
```

### Update flake inputs
```bash
sudo nix flake update
```

### Git workflow

Every change made by the AI assistant must be committed atomically with a
clear, descriptive commit message. Commit after each logical change (not
batched at the end).

```bash
git add -A
git commit -m "scope: description of the change"
```

Remote is `origin` pointing to `git@github.com:DenisSud/nixos-config.git`.
Push after each commit:

```bash
git push origin main
```

## Dotfiles Setup

After a fresh install, clone and link the dotfile repos:

```bash
# Clone repos
git clone git@github.com:DenisSud/dotfiles-shell.git ~/.dotfiles-shell
git clone git@github.com:DenisSud/dotfiles-nvim.git ~/.dotfiles-nvim
git clone git@github.com:DenisSud/dotfiles-pi.git ~/.dotfiles-pi

# Symlink everything
fish ~/.dotfiles-shell/fish/dotfiles.fish link
```

## Important Paths

- Hardware configs: `hosts/*-hardware.nix` (generated by `nixos-generate-config` — do not edit)

## Common Tasks

### Add a new system package
Edit `modules/shell-utils.nix` (for shell tools) or the relevant functional module → `environment.systemPackages`.

### Add a new user package
Edit `modules/user.nix` → `users.users.denis.packages` for packages on both
hosts, or set `denis.userPackages` in the host file for host-specific packages.

### Add a new feature module
1. Create `modules/<feature>.nix` that declares
   `options.denis.<feature>.enable = lib.mkEnableOption "<feature>"` and wraps
   its config in `config = lib.mkIf cfg.enable { ... };`
2. Import it from `modules/shared.nix` (it stays inert until enabled)
3. Enable it per host with `denis.<feature>.enable = true;`

### Add a new host
1. Run `sudo nixos-generate-config --flake .#hostname` and save the hardware config to `hosts/<hostname>-hardware.nix`
2. Create `hosts/<hostname>.nix` — import `../modules/shared.nix`, set the
   `denis.*` values, and add any host-specific hardware config
3. Add the new host to `flake.nix` → `nixosConfigurations`

### Rebuild after hardware changes
```bash
sudo nixos-generate-config --flake .#pc --show-hardware-config > hosts/pc-hardware.nix
```

### AniMe Matrix (lid display)

`denis.asus.animeMatrix.enable` installs `anime-matrix`
(`pkgs/anime-matrix/`), which renders a source to the panel's aspect with
ffmpeg and pushes it through asusd via `asusctl anime`. asusd keeps
running: the third-party AniMe apps (`animatrix` and friends) ask you to
stop it because they open the USB device directly, and that costs the fan
curves and profile switching.

```bash
anime-matrix presets                 # the 34 gifs asusctl ships
anime-matrix preset "ROG glitch"     # play one of them
anime-matrix show ~/vid.mp4 --fps 12 # image, gif or video
anime-matrix text "DENIS"            # static text, auto-sized
anime-matrix text "ON MY LID NOW" --scroll
anime-matrix stop                    # clear the panel, forget the choice
anime-matrix status                  # what plays, brightness, panel switches
anime-matrix brightness low          # off|low|med|high, whole panel
anime-matrix battery off             # stay lit on battery (default: dark)
```

- The last choice is replayed at login by `anime-matrix.service` (user
  unit); prepared frames live in `~/.cache/anime-matrix`, the choice in
  `~/.local/state/anime-matrix/current`. Changing the animation needs no
  rebuild.
- Sources: anything ffmpeg reads. They are scaled to 78x48 (the panel
  rect aspect), padded black and quantised to 16 greys. `--size 74x36`
  matches the framing of ASUS's own gifs.
- Still images are written once (`asusctl anime image`) and stay on the
  panel; gifs and video stream frames from a foreground process
  (`asusctl anime gif --loops 0`), which is why they live in the user
  service.
- The GA401 panel is dark on battery by default (`off_when_unplugged` in
  `/etc/asusd/anime.ron`), and `rog-control-center` only exposes
  brightness and the builtin animations — no image/gif picker.
- Angles, rotation and offsets are asusctl options this wrapper does not
  expose; call `asusctl anime gif --path f.gif --angle 0.5` directly for
  those.

### Voice typing (Parakeet v3)

`denis.voiceTyping.enable` installs the `parakeet` IBus engine, the
`parakeet-indicator@denis` GNOME Shell extension (floating waveform pill),
and a user service that installs the `Super+Alt+V` keybinding and enables
the extension at login.

```bash
parakeet-typing doctor --mic    # model, IBus, keybinding, extension, mic
parakeet-typing status          # engine state + dataset counters
parakeet-typing stop | cancel   # CLI equivalents of the hotkey / Escape
parakeet-typing stream f.wav    # exercise the streaming pipeline headless
```

- After the first rebuild (or a GNOME Shell version change) **log out and
  back in**: GNOME only discovers system extensions at shell startup. IBus
  can be refreshed without a logout with `ibus restart`.
- The engine shows a live preedit, commits when the endpointer decides the
  user is done (0.6 s of clean silence, 1.2 s while the tail is still noisy,
  plus 0.25 s while the hypothesis is still changing) or on a second hotkey
  press, and stays active for a 15 s correction window to capture manual
  edits. The final decode is trimmed of the trailing hangover and falls back
  to the last non-empty partial if the transducer returns nothing, so a
  finished transcript is never dropped.
- Dataset (audio + transcripts + corrections) is append-only under
  `~/.local/share/parakeet-typing/`. `parakeet-typing review` replays
  utterances and saves corrected text; `parakeet-typing export --out DIR`
  writes a Hugging Face audiofolder dataset.
- The model is fetched at build time (671 MB int8) and kept in the Nix
  store; inference is CPU-only on purpose (~35-40x realtime).
- If the mic is muted, `doctor --mic` warns; unmute with
  `wpctl set-mute @DEFAULT_AUDIO_SOURCE@ 0`.
- Implementation lives in `pkgs/parakeet-typing/` (Python engine, VAD,
  dataset, CLI), `pkgs/parakeet-indicator/` (GNOME Shell extension), and
  `modules/voice-typing.nix` (wiring).

### Update Pi to the latest upstream code
`pi` is not the nixpkgs `pi-coding-agent` package (that one is bumped by a bot
and lags weeks behind). It comes from the `pi` flake input
(`github:earendil-works/pi/main`), built from source:

```bash
nix flake update pi
nh os switch          # or: sudo nixos-rebuild switch --flake .#pc
```

A bump costs ~1 min of local build (no binary cache); the model catalog is
pinned in the upstream repo, so the build works offline.

- `main` is tracked on purpose, not a release tag: tag builds can fail upstream
  (v1.2.0's did — esbuild missing from the install lock), and upstream's
  `stable` branch fast-forwards to a tag only after that tag builds, so it can
  lag a whole release.
- If a bump does not build, roll back with `git checkout flake.lock`.

## Notes

- Both hosts import the same shared layer (`modules/shared.nix`) — host files only differ in `denis.*` values and genuinely host-specific hardware config (NVIDIA/Prime, file systems).
- The firewall is on by default (`denis.firewall.enable = true`) with explicit allowed ports (SSH on 22); pc sets `denis.firewall.enable = false`.
- Pi agent uses declarative config only; runtime state (sessions, auth) is per-device.
- `pi` follows the upstream flake input `github:earendil-works/pi/main` — see
  "Update Pi to the latest upstream code" above.
- `nh` runs weekly garbage collection automatically.
- Voice typing logs audio/transcripts by default for fine-tuning;
  `parakeet-typing export` builds the dataset and `{"log_audio": false}`
  in `~/.config/parakeet-typing/config.json` disables audio capture.
- Dotfiles are managed as independent git repos, not through NixOS (this is intentional — see "Dotfiles Setup" above).
